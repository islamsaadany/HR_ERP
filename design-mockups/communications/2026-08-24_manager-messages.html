The manager's own messages

The last piece of Communications, and the only one still unbuilt — everything else is on main. A manager needs to reach their own waiting congratulations without going through the admin. Two surfaces: a sidebar entry with a count, and the page behind it. Illustrative content.

Already built and working: HR’s queue at /admin/communications/queue reaches exactly the same drafts, with the same editor and the same Send. So the feature works end to end today — a manager just cannot yet self-serve, and has to be sent a link.

1 The sidebar entry

Below the divider, in the gold block where Admin and Manage Learning already sit — that block has meant “a door you hold, not a page everyone has” since the beginning. Only somebody with a draft waiting sees it: an entry that is empty most of the year trains you to ignore it.

What I’m assuming — correct me and I’ll change it

  • The entry appears only when something is waiting, and disappears again. An always-present entry that is empty eleven months of the year is one nobody looks at.
  • Called “Messages to send”, not “Congratulations” — it says what is being asked of them.
  • Rows open closed, one at a time.
  • Everything is editable, including the subject. It carries their name.
  • This is the SAME row component HR’s queue already uses — already built, already working. The only difference is that HR’s shows whose draft it is, and a manager’s does not need to.
  • No new permission. A manager sees exactly the drafts assigned to them, which the server already enforces; this is a shortcut to them, not a grant.

Approve and it is two small files — the page and the sidebar entry. Everything behind them is built and verified.
