Which one

 Option A — pool firstOption B — pinned bar
What changes The pool card moves above the benefit list on mobile only (order on the grid children). The full card stays where it is; a condensed summary is pinned to the bottom of the screen while scrolling.
Balance visible… On arrival. Scrolls away once you start browsing. Always, including while you fill in a claim.
Cost One line of CSS. No new markup, no new component. A new mobile-only element, ~64px of permanent screen space, and it overlaps the last row unless the page gets bottom padding.
Matches the docs No — PROJECT_DETAILS.md:81 would be corrected to describe this. Yes — restores the “pinned floating bar on mobile” that is still documented.
Risk Very low. Desktop untouched, nothing overlaps. Moderate. A fixed element competes with the claim form, the toast (bottom-left) and mobile browser chrome.
My recommendation ✓ Start here Worth doing later if people still say they lose track of the balance.
Option A shipped (2026-08-15). One line — order-first lg:order-none on the summary column. Note the pool card lands under the gold section band rather than above it, because that band sits outside the two-column grid: the order reads section header → your balance → the benefit list, which is the right way round. Desktop is untouched. Option B is strictly better for someone deep in a long list, but it permanently spends about an eighth of a phone screen and introduces a fixed element that has to coexist with the claim form and the success toast. If you want the documented behaviour restored exactly, pick B and I'll handle the collisions; otherwise A now, and B only if the need shows up in practice.
